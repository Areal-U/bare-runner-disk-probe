# Optional Chromium source input

The normal entry directly fetches its pinned Chromium revision and Linux/Android dependencies. No source manifest is installed in this preparation branch. R28 cannot opt in. The APK, checkpoint, owner lease, signing destination and recovery paths have independent identities.

For a later owner-bound campaign continuing the reviewed 2.0.4 inputs, the Bare operator may select one **already retained public source Artifact**:

1. Use the existing guarded `next_build/trials.py` selector for `source-chromium`. First find the existing run for this mode and exact preparation SHA. Use a successful unexpired generation. Never dispatch twice for one mode/SHA or commit a no-op to replace an expired pack. Eligible free and noncompeting trials may be run on a genuinely new reviewed work revision. After expiry the build can proceed directly without a seed.
2. Obtain the real source-only producer and comparison result. The following GET-only command emits the exact fixture for full-solution qualification. Use a new reviewed diagnostic revision to replace `next_build/trials/android-source-receipt.json` only if such qualification is needed. Then the same guarded `source-android` selector runs the ordinary pinned source solution in its real Bare builder.

   ```sh
   python3 -I next_build/source_artifact.py receipt "$SOURCE_RUN" "$SOURCE_HEAD" > /tmp/bare-source-receipt.json
   ```

3. A successful full-solution job must retain its immutable physical job record and log. Its before/after root objects, Git tree and commit, V8, dependency entries, Android SDK/NDK and disk/inode floor must pass. Reuse that qualification for a reissued Artifact only when the new verified pack SHA/bytes, file count, tree, official origin and all source pins match. Its current Artifact ID/digest and the original qualification's Artifact ID are recorded separately. Changed input bytes need a new qualification. The real source trial independently binds the original physical Artifact and successful producer.
4. Generate the candidate manifest outside the repo. The command performs only reads, validates exact physical job log measurements and enforces both the Git-only and full-solution benefit at the **number of eligible uses during this actual expiry**. Compare fastest observed direct checkout (508 s in R28; R27 784 and 803 s) with full seeded fetch plus Artifact download, accounting once for generation, upload and handoff. Local tests of the exact 1,445,132,120-byte pack found 2.08–4.18 seconds additional ZIP copying and outer/inner hashing beyond the normal download’s existing extraction. Reserve 5 seconds per pack of that size, scaled up for larger inputs. Hosted network variation is not bounded by this single-machine processing comparison. This is a conservative historical comparison, not a matched repeated direct measurement. Budget 442 minutes between sequential uses plus 45 minutes for the last source stage, allow for actual queue delay in the supplied UTC cutoff, and recheck before each use. If a build finishes before its planned reuse, the saving may not materialize. Choose direct for a job expected to finish in one slot.

   ```sh
   python3 -I next_build/source_artifact.py issue "$NEW_CAMPAIGN" "$SOURCE_RUN" "$SOURCE_HEAD" \
     "$ANDROID_RUN" "$ANDROID_HEAD" "$LAST_USE_UTC" "$PLANNED_SLOTS" > /tmp/bare-reviewed-source-plan.json
   ```

   Both commands require readable GitHub job logs. A Bare operator using an already authenticated GitHub connector may pass `--owner-captured-job-logs DIRECTORY` with separate exact original `<job_id>.json` captures. Preserve the complete decoded log verbatim in `log`, the numeric `job_id`, the `repo_full_name` and the SHA-256 of its UTF-8 bytes in `log_sha256`. The decision still rechecks the hosted run, physical job ordinal, success, artifacts and immutable refs. Capture integrity is the responsibility of the authenticated operator. The manifest retains both full log hashes for independent reread before selection. A hand-written summary or individual timing is insufficient.
5. Only after reviewing the candidate manifest and the separately rebound owner campaign, use it as `next_build/reviewed-source-plan.json` in that candidate's reviewed diff; otherwise omit it. The normal entry has no new dispatch input or token grant. Existing collection and storage admission still run before the first and each subsequent compute slot; they count the already retained Artifact among all visible bytes. The builder uses no extra Actions uploads, cache, new ticket or checkout credentials. The optional read uses the VM's existing read token with a 3-minute limit. Only a successful stage can mark the input usable for the container. Outer ZIP and sole inner file size and SHA are checked; the unprivileged builder verifies the pack and Git objects into a disposable staging directory.

The existing clock, pinned Bare Dockerfile and OS image, Ubuntu dependencies, depot bootstrap, full Linux/Android .gclient sync, hooks, patches and build continue through their normal stages. Restore is capped at 4 minutes and the first seeded sync at 17, within the original source watchdog of 40 minutes. A failing optional fetch/restore selects direct source; an interrupted optional sync discards only its own fresh workspace and retries directly within the remaining watchdog. A surprising pre-existing src stops. The direct retry can still hit the original deadline. Recheck actual clock and disk on any future trial, particularly if GitHub queues exceed the reserved window. Future version or lineage changes require the normal input renderer and campaign review before any seed can be proposed.
