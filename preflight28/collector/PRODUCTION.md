## Exceptional replacement

A pending or expired Actions row does not establish data loss. Reconcile the owner ledger by exact operation, source attempt, slot, destination and version, list and download staged ciphertext/signed/final versions, and reconcile outstanding uploads, signed-but-unpublished files and lost replies with the owner storage provider. Inspect both Draft buffer names and bounded retry names, original temporary outcomes, journals and exact cache. Delay while any producer, collector or private write is unsettled. If **positive** absence is established after closure and every live source (including a partial Draft) is exhausted, the same registered collector can attest the closed owner ledger. The separate owner-issued loss ticket pins the evidence's exact ID/SHA and original claim; `control/loss_resume.py` independently checks the physical job, two complete inventories, original parent and original producer before admitting one replacement. The collector does not issue an automatic replacement dispatch. A surviving original or any conflicting late result must be reconciled using the original campaign ledger before signing or publication.
