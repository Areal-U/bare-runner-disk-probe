# Android工程群を2台に分けたときの純短縮を測る

Bareの試験枝にある既存の `bare-disk-probe.yml` から `split` を選ぶ。共通入口の競合・無料容量判定を通した同じrunで `bare-next-split.yml` がUbuntu 24.04標準VMを2台要求する。分散採否を調べる担当はBare成果担当。通常のビルド、回収・署名が競合している間は投入しない。環境設定、長期秘密、予約は不要。

## 同一仕事と受領条件

対象は2.0.4のChromium `800628ad` がDEPSで参照する公開libyuv `1e2e3a35` と ICU `2a51536d`。libyuvの4つのARM64 GNグループの51翻訳単位と、ICUの `icu18n_sources` のうちソースが大きい順に96個の異なる翻訳単位を使う。同サイズは名前順。2.0.8が選ばれたことは意味しない。固定Chromium Clang 24、NDK r30、Android API 29、ThinLTOを使い、独立VMが公開ソース・ツールを個別に取得する。2台ともローカル2並列。実APKのGN全引数、PGO、生成PCM、終盤DEX、親キャッシュの転送費用は含まない。フルAPKに対する速度や互換性はこの試験だけで判断しない。

受取VMは一時鍵を発行して公開証明書のみを渡し、74件をコンパイルする。相手は73件を作成し、オブジェクトとdepfileを試験・run・attempt・入力識別子に結び付け、暗号化して1回渡す。非公開の親キャッシュ、署名鍵、作業者の情報は一切入力しない。受取側は全件をNinjaの依存状態に取り込み、相手の73件を再コンパイルせず同じアーカイブを作成し、続くNinjaが `no work to do` を返すことを検査する。受取VMの新規出力ディレクトリで同じ147件を最初から2並列で作り、全294のオブジェクト・depfileハッシュおよび最終アーカイブSHAの完全一致を要求する。別attempt、部品欠落、ハッシュ不一致、受取待ち5分、7 MiB超の暗号文は停止。公開証明書と暗号文の保存は合計8 MiB以内、1日限り。各送信の直前に1ファイルの実サイズ＋64 KiBの外装、別runの有無、二重照合した全Artifact、残存期限を再検査する。指定上限と設定済みのリポジトリ上限のうち小さい方を使い、重複名は拒否する。アーカイブや鍵を公開リリース・キャッシュへ保存する処理はない。

## 比較の読み方

実行のまとめに転送バイト、2台が使えるようになった時刻差、準備、コンパイル、受領、統合、空きディスク・inode・メモリの各時点、および同一VMで測った単独計算を含む1台比較値を出す。分散は最初のVMが動いた時から照合まで。1台比較値には受取VMが動くまでの待ち、共通のチェックアウト・準備、直列対照を含め、試験専用の鍵・中継は除く。単独計算は受領後の同じVMで行うため入力のページキャッシュは温まっている可能性がある。どちらのVMも動く前の共通待ちを差に算入しない。VM時計の秒単位の揺れを小差の採否に使わない。

まず全受領条件を満たすこと。2台の総壁時間が1台以上ならこの分割は採らない。正の差はこの工程群についてのみ有効。実行対象区間で他に必要な親・ソース・生成入力の配送、再統合、無料枠占有をその差から引いた後も短縮が残り、重い工程で再現する場合に限り採用候補とする。今回の小さい51件対照では協調前の残り約1秒、147件では局所結果の残り約9.7秒。共有ホスト上の参考値のため物理2台の純短縮には換算しない。

## ローカルの再現

空の `RUNNER_TEMP` を用意し、`NEXT_SPLIT_GROUP=field` をエクスポートする。`bash preflight28/next_split/prepare.sh` は公開2リポジトリを固定SHAで取得し、SHA256で照合済みの公式Clang、NDKヘッダを展開する。`ninja`、`python3.11+`、`openssl`、`git`、`curl`、`tar`、`unzip` が必要。作業ディレクトリ `$RUNNER_TEMP/next-split` で、チェックアウト内 `cohort.py` に `central`、`peer` を別プロセスで渡す。`peer/shard.zip` を `./shard.zip` として渡し、`join` と `solo` のJSONを比較する。実ネットワークを使わず暗号経路、古いattempt、欠落・破損を検証する入口は `python3 preflight28/next_split/test_integrity.py`。
